# i18n (Internationalisation)

## Framework

`react-intl` (ICU Message Format).

## Structure des fichiers de traduction

Fichiers `lang.json` avec un objet par langue :

```json
{
  "en": { "KEY_NAME": "English value" },
  "fr": { "KEY_NAME": "Valeur française" }
}
```

- `en` est la langue de fallback — toujours obligatoire.
- Les autres langues sont optionnelles dans les fichiers JSON (le serveur fournit la plupart des traductions complémentaires via ses propres ressources).
- Langues supportées : `en`, `fr`, `de`, `it`, `es`, `pt`, `pl`, `ro`, `nl`, `tr`, `fl`.

## Convention de clés

`UPPER_SNAKE_CASE` avec préfixe de domaine :

| Préfixe | Scope |
|---------|-------|
| `GLOBAL_` | Clés partagées entre packages / projets |
| `CALENDAR_`, `BOOKMARK_`, etc. | Clés spécifiques à un domaine |
| `APP_{Name}_` | Clés d'une extension |
| `WIDGET_` | Clés liées aux widgets |

Les projets externes utilisent leur propre préfixe cohérent avec le nom du projet (`APP_{Name}_Key`).

## Emplacement des fichiers

| Scope | Fichier |
|-------|---------|
| Composants UI partagés | `src/translation/lang.json` du design system |
| Application principale | `src/translation/lang.json` de l'app |
| Par extension | `src/extensions/{Name}/translation/lang.json` |

Règle : les clés vont dans le `lang.json` du package ou du projet où elles sont utilisées. Les clés `GLOBAL_*` partagées vivent dans le design system.

## Utilisation

```typescript
// En JSX
<FormattedMessage id="CALENDAR_Event" />

// En code
const intl = useIntl();
intl.formatMessage({ id: 'CALENDAR_Event' });
```

## Syntaxe ICU

```json
{
  "en": {
    "ITEM_count": "{count, plural, one {# item} other {# items}}"
  }
}
```

Variables : `{count}`. Pluriels : `{count, plural, one {...} other {...}}`.

## Enregistrement dans les extensions

Chaque extension charge ses traductions au bootstrap :

```typescript
import lang from './translation/lang.json';
jCore.translation.addResources(lang);
```

Ce chargement se fait **une fois**, typiquement dans le `index.tsx` de l'extension. Jamais dans un composant à chaque montage.

## Développement local

Travailler en anglais uniquement en local. Le support multi-langue est géré au déploiement via les ressources serveur.

## Règle d'or

**Aucune chaîne affichée à l'utilisateur ne doit être en dur dans le code.** Tout passe par `intl.formatMessage` ou `FormattedMessage`. Un label de bouton, un message d'erreur, un titre de modal, un texte d'aide — tout a une clé dans `lang.json`.
